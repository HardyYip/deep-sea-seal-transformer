# 项目说明与简历表述参考

## 可由代码和产物支持的工作

本项目的技术工作包括：28 个 training CSV 的结构审计与溯源合并、配套 CSV/XLSX 证据复核、异常保留及暂时排除、共享节点关联检查、固定清单划分、双模型实现、训练集标准化、GPU 运行预检、训练/验证/测试隔离和无标签推理。

核心工程决策是把节点三通道和全局压力分开建模；把共享节点状态视为潜在关联，防止跨分区；用训练集统计完成可逆标准化；在权重与数据指纹一致时才允许评价或推理。公开合成检查覆盖端到端链路，实际研究成绩单独保留为冻结汇总。

## 简历表述参考

以下是项目事实模板，应按本人实际负责、理解并能独立解释的部分取舍。代码实现与文档整理使用了 AI 辅助；数据来源、项目归属和个人职责应如实说明，不将辅助完成的工作描述为完全独立开发。

**深海柔性密封性能预测｜Python、PyTorch、Transformer、多输出回归**

- 面向两个数据分组构建独立 Transformer 回归模型，融合 221 个节点的三通道特征与全局压力，分别预测 ff、f、q，并输出原尺度摩擦力 ff+f。
- 建立覆盖来源哈希、稳定样本 ID、异常证据与关联组隔离的数据流程；在 2,093 条原始工况中按记录暂时排除 3 条，将 11 条共享节点记录归入同一分区，降低已知关联泄漏风险。
- 使用仅训练集拟合的标准化、验证集早停和独立留出测试；在 302 条冻结测试记录上，六项分组目标 R² 为 0.9754–0.9990，相对训练均值基线的 RMSE 降低约 84.4%–96.8%。
- 提供 CUDA 实际前向/反向预检、checkpoint 指纹核验、无目标列 CSV 推理和 GitHub Actions 合成端到端验收。

## 面试时值得讲清楚的设计

1. **一个样本是什么**：一行是一组工况，221 个节点不是 221 个训练样本；直接拆节点会改变任务并引入泄漏。
2. **为什么压力单独输入**：节点表示先经自注意力与池化，全局压力经独立分支，再融合预测。
3. **为什么不用时间编码**：数据没有时间列，节点物理对应和拓扑未完全确认；当前使用节点集合表示，在推理模式下对整体节点置换不变。
4. **如何避免标准化泄漏**：均值/尺度仅来自 train，保存拟合 ID；目标逆变换后计算指标和 ff+f。
5. **为什么共享节点要分组**：即使压力不同、完整输入不相同，重复节点状态也可能使留出评价过于乐观；采用保守关联隔离。
6. **如何理解高 R²**：当前是给定节点输入、当前压力范围的代理回归，尚未证明两压力直接预测、外部数据泛化、工程可部署或 Transformer 优于强基线。
